# C2-15 LOLRMM: RMM registry keys

| | |
|---|---|
| Tactic | TA0011 Command and Control |
| ATT&CK | T1219 Remote Access Tools, T1112 Modify Registry |
| Indexes | `registry-*`, `evtxlogs-*` |
| Needs | Sysmon 12/13/14, and/or RECmd batch output that dumps the vendor keys |
| Roles | all (baseline) |
| Source | [LOLRMM](https://lolrmm.io) catalog, generated by [`tools/lolrmm.py`](../../../../tools/lolrmm.py): do not edit `query.esql` by hand |

**What it finds.** Registry keys LOLRMM lists for RMM tools (`HKLM\SOFTWARE\ATERA Networks\AlphaAgent`, `HKLM\SYSTEM\CurrentControlSet\Services\<RMM service>`, Uninstall entries, `SafeBoot\Network\ScreenConnect Client (*)` ...) in Sysmon registry events and in RECmd batch output. Keys are compared without the hive name and without `WOW6432Node`, so `HKLM\SOFTWARE\X` matches RECmd's `ROOT\X` as well as Sysmon's `HKLM\SOFTWARE\WOW6432Node\X`. One row per host, tool, source and key, with the values and data seen and, for Sysmon, the program that wrote the key.

**Reading the output.** Sorted by score: 2, +1 for a Sysmon event (it has the write time and the program), +1 for a key under `SafeBoot`, `Policies`, `Services` or `Run` (persistence that survives Safe Mode, a pushed policy, a service), +1 when only one host has it. A key in `SafeBoot\Network` lets the RMM run in Safe Mode with Networking, a trick ransomware operators use before encrypting.

**Limits.** RECmd's batch files dump chosen keys only; without Sysmon this query sees the vendor keys only if the batch file (for example a full-hive dump) included them. Services and Uninstall entries are also covered by [C2-12](../C2-12-lolrmm-rmm-services-and-tasks/) and [TRI-05](../../00-triage/TRI-05-installed-software/).

**If it errors.** Remove the family that is not loaded from `FROM`, or let `SOF-ELK_RunChecklists.py` stub the missing fields.
