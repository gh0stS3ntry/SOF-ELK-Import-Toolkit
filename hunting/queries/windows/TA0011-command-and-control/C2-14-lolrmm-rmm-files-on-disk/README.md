# C2-14 LOLRMM: RMM install folders, programs, logs and configuration files on disk

| | |
|---|---|
| Tactic | TA0011 Command and Control |
| ATT&CK | T1219 Remote Access Tools, T1105 Ingress Tool Transfer |
| Indexes | `filesystem-*`, `evtxlogs-*` |
| Needs | MFTECmd `$MFT` output and/or Sysmon 11 |
| Roles | all (baseline) |
| Source | [LOLRMM](https://lolrmm.io) catalog, generated by [`tools/lolrmm.py`](../../../../tools/lolrmm.py): do not edit `query.esql` by hand |

**What it finds.** Files in the `$MFT` (live and deleted entries) and files created according to Sysmon 11 that match an LOLRMM install folder, program, log or configuration file (`\Program Files\TeamViewer\Connections_incoming.txt`, `\ProgramData\AnyDesk\ad_svc.trace`, `\Users\*\AppData\Roaming\RustDesk\config\RustDesk.toml` ...), or whose name is an RMM program name wherever it is (`anydesk.exe` in `Downloads`). One row per host, tool and folder, with the number of files, executables and deleted entries, the first and last creation time and up to 20 file names.

**Reading the output.** Sorted by score: 2, +1 if the folder holds executables, +2 for a user-writable folder, +1 when entries are deleted (uninstalled or cleaned up), +1 when only one host has the tool. The tool's own logs are the best evidence of what was done through it: AnyDesk `ad.trace` / `ad_svc.trace` and `connection_trace.txt`, TeamViewer `Connections_incoming.txt`, ScreenConnect and Splashtop logs. Collect and read them from the image; the toolkit does not parse them.

**How it stays fast.** A `$MFT` has millions of rows. The first `WHERE` runs one regular expression (Java, through `REPLACE`) that keeps only paths containing a folder or file name that some LOLRMM pattern requires; the full patterns are tested on what is left.

**If it errors.** Remove `evtxlogs-*` from `FROM` if no event logs were loaded (or `filesystem-*` if no `$MFT`), or let `SOF-ELK_RunChecklists.py` stub the missing fields.
